# mm-recsys PDF 요구사항·성능 감사

2026년 11월 21일, 로컬 작업본으로 기본 `full-v44` 이미지를 빌드했다. 이 시스템은 합성 쇼핑 카탈로그에서 텍스트·이미지를 검색하고 고객의 장기 이력과 현재 세션으로 상품을 추천한다. PDF가 정한 단일 사용자 요청과 상품 5만 개·고객 1만 명·이벤트 100만 건을 기준으로 평가했다.

**성능 기준 11개와 최소 후보 300개는 통과했다. PDF 전체 판정은 부분 충족이다.** 기본 실행의 대시보드, 새 폴더 설치 경로, 제출 증거 및 코드 품질에 확인된 차이가 있다. 제공된 과제 원문 `멀티모달_검색_및_Multi-Stage_추천_시스템_구축.pdf` · [상태·출처 검사](audit.json)

## 정량 기준

기본 열은 이번 full test와 별도의 실서비스 경로 HTTP·Redis 벤치마크 실측이다. 교정 열은 11월 15일의 별도 `full-realism-v4` 실행이다. 이번에 교정 데이터 파일 해시와 valid 동결 기록을 확인하고 보존된 수치 11개를 원본 집계 필드에서 재계산했다.

검색은 세 모드 각각 200개씩 600개 쿼리의 평균이다. 추천 Recall@300은 평가 시점에 등록된 전체 카탈로그에서 후보를 검색해 미래 cart/purchase 고유 상품에 대한 사용자별 재현율을 평균했다. 이번 test의 정답 보유자는 7,012명, Coverage 모집단은 10,000명이다. 후보 수, 다양성 위반, 제약을 만족시킬 수 없는 후보 풀도 품질 판정에 포함했다. 학습 seed는 42이고, 기존 동결된 모델을 재사용하여 현재 소스로 valid를 먼저 통과한 후 test를 평가했다. ## 오프라인 품질과 추천 효과

- 기본 full에서 인기순 → Two-Tower → DeepFM → 재정렬 후 최종 추천의 NDCG@50은 각각 0.0152, 0.1651, 0.3818, 0.3299였다. 최종 추천은 인기순과 Two-Tower를 앞섰고 DeepFM 단독보다 낮았다. 검색의 텍스트·복합 쿼리에서는 BM25가 MRR 1.0이었다. 합성 상품 50,000개에서 CLIP에 입력된 고유 텍스트는 1,440개, 고유 이미지는 256개였다. 일반 쇼핑몰 실사진 검색은 별도의 평가가 필요하다. [기본 test의 검색·추천 베이스라인](quality_full_test.json)
- 계약상 랭킹 AUC 문턱은 클릭 확률인 CTR에 적용한다. 기본 모델의 구매 예측 CVR AUC는 0.5304, 교정 모델은 0.5052였다. 교정 test에서 cold 사용자 300명 중 미래 구매·장바구니 정답 보유자는 0명이어서 이 집단의 추천 적중 품질은 미측정이다. [평가 계약](../../../../contracts.md) · [교정 실험](../realism_full_20261115/report.md)
- 이번 인기순 대 전체 추천 합성 A/B는 각 500명·7일이었다. CTR은 24.97% → 20.78%로 상대 -16.81%, CVR은 1.22% → 0.94%로 상대 -23.36%였다. CVR 차이의 95% 신뢰구간은 [-0.446, -0.126]%p, p=0.000464397다. PDF 12쪽의 +28%는 출력 예시다. 효과 크기는 합성 반응식에서 관측한 값이다. [이번 실험](ab_test.json) · [통계 재검산](ab_test_verification.json)
- 기본 full의 기존 5,000명/군·30일 실험에서도 CTR −17.37%, CVR −27.72%였다. 교정 full의 500명/군·7일 실험에서는 CTR −39.56%, CVR −54.90%였다. 추가 실데이터 H&M 평가에서 10만 학습 고객 멀티모달 모델의 Recall@300은 0.0599였다. PDF 합성 데이터 기준 통과를 실제 구매 성과 개선으로 일반화할 근거는 부족하다. [5,000명/군 실험](../../../../submission/report.md#L69) · [교정 full 실험](../realism_full_20261115/report.md#L53) · [H&M 구매 검증](../../../../external_datasets.md#L153)

## PDF 전체 충족을 막는 항목

1. **기본 기동에서 대시보드가 빠진다.** PDF 2·5·12쪽은 한 번의 Compose 명령으로 API·Redis·시뮬레이터와 8501 대시보드를 실행하도록 요구한다. 현재 작업본에서 기본 명령으로 기동한 서비스는 API·Redis·시뮬레이터·쇼핑몰 네 개였다. Streamlit을 기본 서비스에 포함하면 쇼핑몰을 유지하면서 평가자가 같은 명령으로 대시보드에도 접속할 수 있다. 공개 main에는 대시보드가 기본으로 들어 있다. 이 차이는 로컬의 쇼핑몰 변경에서 생겼다. [Compose 설정](../../../../../docker-compose.yml#L58) · [실행 기록](deployment_checks.json)
2. **평가 결과가 없는 첫 실행에서는 차트가 비어 있다.** 별도 프로필로 대시보드를 켠 뒤 Chromium에서 여섯 탭을 열 수 있었지만 검색·추천·A/B 탭의 차트는 각각 0개였다. 이 상태에서는 PDF 2쪽의 결과 화면을 볼 수 없다. 현재 배포의 데이터·모델과 일치하는 검증된 결과를 초기화 시 제공하거나, 결과가 없을 때 평가와 A/B를 실행하는 제출용 기동 절차가 필요하다. [최초 화면의 실제 문구](dashboard_initial.json) · [대시보드 결과 선택](../../../../../dashboard/app.py#L215)
3. **빈 폴더로 설치하는 경로에서 쇼핑몰 빌드 입력이 누락된다.** `bash setup_env.sh <빈 폴더> --scaffold-only --skip-docker-check`는 종료 코드 0을 반환했다. 대상에 Dockerfile과 Compose는 생겼지만 Dockerfile의 `COPY`가 요구하는 `storefront/package.json`과 잠금 파일은 없었다. 전체 회귀 524개 중 523개가 통과했고 정확히 네 서비스만 허용하는 설치 테스트 한 개가 실패했다. 설치 스크립트에 쇼핑몰 소스 복사를 추가하고, 설치 테스트는 필수 서비스의 기본 기동 여부와 각 Dockerfile의 필수 입력을 검사하도록 맞추는 것이 최소 조치다. [설치 복사 범위](../../../../../setup_env.sh#L51) · [Dockerfile 입력](../../../../../docker/Dockerfile.storefront#L4) · [빈 폴더 재현](scaffold.json) · [전체 회귀 결과](pytest.txt)
4. **제출 요구사항표의 출처·해시가 실제 파일과 다르다.** 제출 검사 `files_check`가 `evidence changed or missing: docs/submission/dataset_scope.json`에서 실패했다. 요구사항표는 실제 데이터를 ‘미획득’으로 설명하지만 현재 출처 파일에는 획득했다고 기록되어 있다. 요구사항표와 제출 보고서의 문구·근거를 함께 갱신한 뒤 현재 소스로 제출 검사를 다시 실행해야 한다. 보관 중인 11월 12일 최종 PASS의 원본 파일 해시 검사는 지금도 통과한다. 그때의 집계와 이번 제출 검사는 입력과 검사 범위가 다르다. [요구사항표](../../../../submission/requirements.md#L22) · [근거 해시](../../../../submission/requirements.json#L237) · [획득 기록](../../../../submission/dataset_scope.json#L8) · [이번 검사](audit.json)
5. **외부 데이터 실험의 주요 함수와 입력 경로가 PDF 9쪽 코드 품질 조건에 일부 미달한다.** 예를 들어 Retailrocket 전이 추정에 쓰는 `observed_pairs`와 `fit`에는 인자·반환 타입이 없다. 새 작업 경로에서 교정을 준비할 때 H&M·Retailrocket의 이전 보고서 두 개는 코드에 고정된 위치에서 읽는다. 핵심 함수의 타입을 명시하고 두 입력 경로를 실험 설정으로 옮기면 실행 환경을 바꿀 때 소스를 수정할 필요가 없다. 이번 `src`·`dashboard`·`docker` 범위에서 mypy는 146개 파일을 통과했고, 별도 AST 검사에서는 공개 함수 48개에 인자 또는 반환 타입 누락이 있었다. PDF의 ‘주요 함수’와 AST가 집계한 ‘공개 함수’는 범위가 다르다. [전이 추정 함수](../../../../../src/external_data/expansion_retail.py#L13) · [고정 경로](../../../../../src/external_data/realism_data.py#L36) · [경로 이동 재현 기록](path_reproduction.json) · [이번 AST 검사](audit.json)
