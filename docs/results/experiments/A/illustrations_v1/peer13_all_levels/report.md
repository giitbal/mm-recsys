# PDF 동료 평가 13번 재검증

**PASS.** PDF 13쪽은 동일 카테고리 상품의 3연속 노출 여부를 표본 3건 이상으로 확인하도록 한다. 대·중·소분류 각각에서 같은 분류명이 최대 두 번까지 이어지는지 검사했다. 대분류가 달라도 중분류명이 같으면 같은 중분류로 계산했다.

## 실제 API의 Top 10

이전 감사에서 시드 42로 선택한 사용자 30명에게 기본 Docker API로 다시 요청했다. 각 응답의 상품 ID를 새 도안 5만 개 카탈로그에 연결하고 출력 순서를 따라 분류별 연속 길이를 직접 계산했다. 모델 버전은 `v1.0`이다. [이전 30명 응답](../peer_review_20261121/sample_30.json) · [이번 응답과 비교 결과](live_30.json) · [기본 서비스 상태](deployment.json)

| 3연속 이상인 사용자 | 변경 전 | 변경 후 |
|---|---:|---:|
| 대분류 | 24 / 30 | 0 / 30 |
| 중분류 | 18 / 30 | 0 / 30 |
| 소분류 | 0 / 30 | 0 / 30 |

예를 들어 `U006437`의 대분류 추천 순서는 아래와 같다.

- 변경 전　tops → tops → footwear → tops → tops → tops → tops → tops → bottoms → tops
- 변경 후　tops → tops → footwear → tops → tops → bottoms → tops → tops → bottoms → tops

30명 모두 서로 다른 상품 10개, 최근 7일 신상품 1개 이상, MAB 탐색 슬롯 2개를 받았다. 기존 사용자와 신규 사용자에게 각각 1·2·3·50·100개를 요청한 추가 10건에서도 요청 수, 세 분류 연속 제한, 신상품과 탐색 슬롯을 확인했다. 기본 동료 평가 명령도 3명 × 3분류를 검사하며 실제 Redis 세션과 함께 통과했다. [크기별 응답](live_30.json) · [동료 평가 실행](native_peer.json)

## 전체 사용자와 추천 품질

기본 v1.0 모델, 5만 상품, 1만 사용자, 100만 행동을 사용했다. 시간순 valid에서 기준을 확인한 후 같은 코드·모델·설정·데이터 해시로 test를 실행했다. 각 시점의 카탈로그와 이력으로 추천했고, 검증 코드는 반환된 실제 Top 50 상품을 세 분류로 다시 매핑해 연속 노출을 집계했다. [동결 입력·설정·자원](frozen_inputs.json) · [valid 원자료](full_valid.json) · [test 원자료](full_test.json)

| 평가 | 사용자 | 서로 다른 상품 50개 | 세 분류 중 3연속 이상 | 7일 신상품 1개 이상 | 탐색 슬롯 2개 |
|---|---:|---:|---:|---:|---:|
| valid | 10,000 | 10,000 | 0 | 해당 없음 (재고 0개) | 10,000 |
| test | 10,000 | 10,000 | 0 | 10,000 | 10,000 |

valid 기준 시점에는 등록 7일 이내 상품이 0개였다. test 기준 시점에는 872개였다. 시점별 상품 재고를 기준으로 신상품 검사를 적용했다.

첫 valid 시도에서 세 분류 모두 3연속은 없었으나 109명이 50개 미만을 받았다. 그중 한 사용자의 후보 300개에는 대분류와 중분류가 동시에 달라지는 상품이 15개뿐이었다. 이 사례를 회귀 테스트에 추가해 후보 단계에서 두 제한을 함께 끊을 상품을 확보하도록 수정한 뒤 valid부터 다시 실행했다. [첫 valid 원자료](initial_valid/full_valid.json) · [후보 조합과 47개 응답](initial_valid/short_response.json)

| 지표 | 기준 | 이전 test | 변경 후 valid | 변경 후 test |
|---|---:|---:|---:|---:|
| Recall@300 | 0.30 | 0.74579 | 0.74896 | 0.74579 |
| CTR AUC | 0.70 | 0.96578 | 0.96665 | 0.96578 |
| HitRate@50 | 0.20 | 0.66515 | 0.68821 | 0.66443 |
| nDCG@50 | 0.08 | 0.32991 | 0.36600 | 0.32928 |
| Coverage | 0.20 | 0.37448 | 0.39640 | 0.38316 |

Recall@300은 재정렬 앞단의 전체 카탈로그 후보 지표다. HitRate·nDCG는 미래 장바구니 또는 구매 정답이 있는 사용자로, Coverage와 연속 노출은 각 분할 1만 명으로 계산했다. [기존 test 근거](../peer_review_20261121/quality_recheck.json)

## 성능과 실행 확인

- 기본 API에 워밍업 10회 후 Top 10을 직렬로 100회 요청했다. HTTP 왕복 p50 22.20ms, p95 28.65ms, 최대 38.98ms이며 200ms 초과는 0건이었다. 100건 모두 3개 분류의 연속 제한을 충족했다. [HTTP 원시 표본](recommend_latency.json)
- Redis를 사용한 전체 테스트 538개가 통과했다. 애플리케이션·대시보드·Docker 코드의 mypy 검사도 통과했다. [pytest](pytest.xml) · [mypy](mypy.log)
- Chromium에서 기본 대시보드가 보관된 통합 성적을 이전 추천 정책의 측정으로 표시하는 것을 확인했다. 변경 후 A/B 효과, CT 승격과 27문항 전체 통합 판정은 이번 검증 범위 밖이다. [대시보드 화면 검사](dashboard.json)

## 재실행

기본 Compose 배포를 준비한 뒤 아래 명령을 실행하면 현재 API에서 3명 × 3분류와 신상품·탐색·세션 검사를 재현할 수 있다.

```bash
docker compose exec -T api-server python scripts/verify_peer_review.py --output /tmp/peer-review.json
```
